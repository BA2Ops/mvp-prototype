# 15 - 经验库设计时可视化（T2）——能力定义

> **状态**：能力定义与预期表达（设计前讨论稿）。
> 关联：[13 方向总览](./13-next-directions.md)、
> [12 Experience 模型](./12-experience-model.md)、
> [17 元数据规范](./17-experience-metadata.md)。

---

## 决策摘要

可视化模块的能力定义：**让「理解一条经验」不需要读 JSON**——
把经验的三段式结构与其编译产物转成人类可直读的图形/结构化表达，
为经验作者提供创作反馈回路，为评审者提供评审媒介。

---

## 一、解决什么问题

1. **阅读成本**：经验是嵌套 JSON（pre 数组 + judgment 条件树 + paths/steps），
   `safe_write` 这样的中等复杂度经验已需要来回跳读才能在脑中拼出流程。
2. **创作反馈缺失**：作者写完经验后，没有直观方式确认「结构是否符合我的意图」，
   只能靠执行来验证（太晚）。
3. **评审无媒介**：他人（或未来的 LLM 辅助设计）产出的经验，评审者需要
   一个快速把握全貌的载体。

## 二、能力边界

**做**：
- 经验静态视图：三段式结构 → 流程图表达（前置链、条件分支、各路径步骤）
- 编译产物视图：L3 编译输出的指令序列 → 「汇编清单」式结构化展示
  （demo-05 已有人读版雏形，本模块使其成为正式能力）

**不做**：
- 不做编辑器（修改经验仍走定义文件 / 未来 LLM 辅助设计）
- 不做执行监控 UI（运行时观测属方向 E trace）
- MVP 不要求交互式 Web 界面（静态生成即可）

## 三、预期输入 / 输出

| | 表达 |
|---|---|
| **输入** | 单条或多条 Experience 定义；可选：对应 intent 的编译产物 |
| **输出** | 人类可直读的图形化表达（如流程图文本格式，可直接嵌入文档渲染）+ 指令序列清单 |

## 四、预期行为表达（示例）

> 以下为**预期效果**的描述性示例，非实现规格。

- 对 `safe_write` 生成静态视图，预期能一眼看到：
  「探测读取 → 判断已存在？→ 是：跳过写入（abort）/ 否：写入」，
  且两条路径各自的回复消息可见。
- 对 `replace_in_file` 生成静态视图，预期能看到三步链的
  寄存器传递关系（读 → 替换 → 写）。
- 对 `demo_branch` 类经验生成编译产物视图，预期能看到
  evaluate_expr / conditional_skip / 跳转目标的对应关系——
  作者据此验证分支构造是否符合预期。
- 批量模式：对整个经验库生成索引页（每条经验一个图 + 概要），
  作为库的「地图」。

## 五、依赖与关联

- 无硬依赖，**可立即做**（不依赖真 LLM / 元数据）。
- **[doc 17 元数据](./17-experience-metadata.md)**：若经验带副作用声明，
  静态视图可标注高危节点（增强，非前置）。
- **[doc 14 搜索](./14-experience-search.md)**：可视化产物可作为
  搜索结果的展示载体（远期）。
- **[doc 16 LLM 辅助设计](./16-experience-llm-assisted-design.md)**：
  LLM 生成的经验草稿，可视化是人审的最佳媒介（强关联）。

## 六、待明确问题

1. 图形表达的载体选择（文本图形格式 vs 自定义渲染）——设计期定。
2. 编译产物视图的详略层级（全指令 vs 折叠到逻辑块）。
3. 嵌套经验在视图中如何表达（展开子图 or 引用链接）。
