## 决策摘要

元数据规范模块的能力定义：**为经验定义「描述性信息」的标准字段集，
并让 L3 编译器消费其中具备引擎意义的部分**——使元数据不只是文档注释，
而是参与编译校验、安全策略与检索的**活数据**。

定位：T1 搜索、T3 辅助设计的地基；其中类型校验与副作用声明两项
即使独立于工具链也直接提升引擎健壮性。

---

## 一、解决什么问题

1. **检索无字段可用**：搜索/查重需要结构化字段（标签、分类），
   当前只有自由文本 description。
2. **类型不校验**：ParamSpec 声明了 type，但编译器不检查
   ParamRef 字面量是否与之相符——声明与实际可以矛盾而不被发现。
3. **副作用不可见**：哪些经验写文件、哪些执行命令，系统无从得知——
   安全策略（高危确认）、编排顺序约束（只读可重排）都缺依据。
4. **演化无版本**：经验修订时无法判断「会不会破坏既有调用方」。

## 二、能力边界

**做**：
- 定义经验的元数据字段集与语义（标准 schema）
- 编译器消费：类型强校验 / 副作用驱动的策略钩子 / 策略参数下发

**不做**：
- 不改变经验的执行语义（元数据是描述与约束，不是新的执行机制）
- 不强制存量经验一次性补齐（渐进迁移）

## 三、预期输入 / 输出

| | 表达 |
|---|---|
| **输入** | 经验定义中的元数据字段（作者手写或 doc 16 生成）|
| **输出 A（编译期）** | 校验结论（类型不符/缺失必填元数据 → 编译失败并指出位置）|
| **输出 B（编译产物）** | 元数据派生的 entry 属性（副作用标记、策略参数）|

## 四、候选元数据目录（预期表达）

> 以下为**预期的字段能力**，具体 schema 设计期定。

| 字段能力 | 预期表达 |
|---|---|
| 标签/分类 | 「按文件操作/命令执行分类检索」可命中正确集合 |
| 类型强校验 | 字面量参数与 ParamSpec.type 矛盾时 → **编译失败**并指出字段 |
| 副作用声明 | 经验自述「只读 / 写文件 / 执行命令」→ 安全策略据此决定是否需确认；编排时只读经验可重排 |
| 版本 + 兼容范围 | 修订经验时能回答「谁在用旧版」|
| 超时/重试策略 | 经验级覆盖全局默认值，编译器写入产物 |

### 预期行为示例

- 一条经验声明 `inputs.path` 为 `path` 类型，但步骤里给了数字字面量
  → 预期编译报错，指明「step X 的 input 'path' 与声明的 path 类型不符」。
- 一条经验声明副作用为 `read-only` → 预期编排器允许它与其它只读经验
  并行/重排；声明 `exec` 的经验 → 预期触发执行前确认策略。
- 未声明任何元数据的存量经验 → 预期能正常编译（渐进兼容），
  但工具链提示「元数据缺失」。

## 六、待明确问题

1. **副作用声明粒度**：经验级还是 step 级？（精细度 vs 声明成本的权衡）
2. 类型系统的强度：ParamSpec.type 目前是宽泛类别（string/number/object），
   是否细化到 path/list<string> 等？细化到哪一层？
3. 渐进迁移策略：存量经验的元数据补齐由人工、doc 16 自动生成、还是混合？
4. 副作用与安全策略的对接方式：编译期拒绝？运行期确认？还是仅标记由上层决定？
