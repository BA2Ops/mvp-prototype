# A10 开发日志 — 异常冒泡机制（错误处置权在 L3）

日期：2026-08-20
前置：A08/A09（execute_intent 帧保留 + l1MainLoop）

---

## 一、背景：用户设计修正

原设计（A7 时代）：L2 op 自己分类"已知错误（OperationError 数据）vs 硬错误（throw）"。
**用户修正**：整体是解释执行，**无论什么错误，是否捕捉和处理由 L3 的经验结果决定**——
L3 写入 L1 指令栈的指令主动带标志位（handleError），表达"当前指令的异常无需 L1 协助处理，
后续指令会进行异常消息寄存器（$r_err）内容判断"。没有标志 → 默认由 L1 递归向上冒泡。

## 二、核心机制

### 2.1 handleError 标志（IntentEntry 必填字段）

```typescript
interface IntentEntry {
  ...
  /** true = 本经验内异常由后续指令检查 $r_err 处理（L1 不冒泡，截获在此层）*/
  handleError: boolean
}
```

- L3 编译经验时设置（错误处置权在编译期）
- false = 默认：异常递归向上冒泡

### 2.2 帧保留语义（execute_intent 重构）

**A8 原实现**：executeIntent 一次性（pop self → push children）→ IntentEntry 帧丢失。
**新实现**：IntentEntry **保留在指令栈中作为调用帧**，children 压帧之上；
children 执行完（栈顶回到帧）→ 主循环标记 done + pop。

```
栈：[root, a_root(帧), a_after, a_intent(B帧), b_after, b_intent(C帧), c_op]
```

帧是异常冒泡的边界（与 CPU 调用栈类比）。

### 2.3 异常冒泡算法（bubbleError）

```
1. 异常信息写入 $r_err（errorToOperationError，保留原始错误码如 ENOENT）
2. 弹出异常点 entry（栈顶，抛错者）
3. 从栈顶向下找最近的 handleError 帧（handler）
4. 无 handler → 全部弹出（标记 aborted）→ UnhandledError 给调用者
5. 有 handler →
   保留 handler 调用链（栈底方向）+ handler 的剩余 children（catch 逻辑）
   弹出 handler 之上的无标志帧链（异常子树）
6. 主循环继续（handler 的 catch 逻辑执行，读 $r_err 判断路径）
```

### 2.4 A/B/C 嵌套冒泡场景（用户描述验证）

```
[A(handleError=true), B(false), C(false)]，C 内 op 异常：
  弹出 C 序列（c_op + C帧）→ 弹出 B 序列（b_after + B帧）
  → 到 A 帧（handler）→ 截获，保留 A 的剩余（a_after）
  → 继续执行 a_after（catch 逻辑）→ A 帧 done → 完成
```

## 三、关键设计决策

| # | 决策 | 说明 |
|---|---|---|
| D-A10-1 | 错误处置权在 L3（handleError 标志），非 L2 op 自分类 | 用户修正核心 |
| D-A10-2 | IntentEntry 帧保留（不一次性 pop） | 冒泡需要帧边界 |
| D-A10-3 | 截获时 handler 帧**保留**（其 children 继续执行 catch 逻辑） | 不是弹出！ |
| D-A10-4 | 异常信息写入 $r_err（errorToOperationError）| 保留原始错误码 |
| D-A10-5 | 无 handler → UnhandledError 给调用者 | 默认冒泡到顶 |
| D-A10-6 | maxSteps 在 try 外（L1 系统错误不走业务冒泡）| 防御机制不被截获 |
| D-A10-7 | skip_n/conditional_skip 不跨帧（帧边界保护）| 保护调用边界 |
| D-A10-8 | L3 mock 每次 compile 返回**新** entries（structuredClone）| 模拟真实 L3，防共享状态 |

## 四、实现要点

### 4.1 冒泡的栈结构约定

帧的 children 压栈时紧贴帧之上；执行顺序 = 从栈顶向栈底：
```
[.., handlerFrame, handlerChildren..., childFrame(无标志), childChildren..., op(异常点)]
```
keepIds 重建栈：保留 [0..handlerIndex] + handler 之上的 keep 模式 entries。

### 4.2 execute_op 已知错误路径（不变）

op 返回 `{ ..., error: OperationError }` → 数据流写 $r_err → DAG 判断。
op throw（任何）→ 主循环 catch → bubbleError（L3 决定处理权）。
