## 2. L2 Op 接口评估

### 2.1 统一接口模式（验证通过）

所有 22 个 op 遵守 `Operation` 接口（`src/l2/operation.ts`）：

```typescript
{
  name: string
  description: string
  formalSpec: { inputs: {...}, outputs: {...} }
  execute: (inputs) => Promise<Record<string, Value>>
}
```

**评估**：✅ 一致性 100%

### 2.2 统一错误模式（验证通过）

所有 22 个 op 遵守 **"已知错误码 → 数据，其他异常 throw"** 模式：

| 错误类型 | 处理方式 |
|---|---|
| 已知 fs 错误（ENOENT/EACCES/EISDIR） | 返回 `{ ..., error: OperationError }` |
| 用户输入错误（INVALID_INPUT/INVALID_REGEX） | 返回 `{ ..., error: OperationError }` |
| 编程错误或未知错误 | throw → L1 bubbleError → L3 handleError 决策 |

**评估**：✅ 完全符合 A10 D-A10-1 "L3 决定（非 L2 自分类）" 原则

### 2.3 formalSpec 完整性

每个 op 都有完整的 `inputs`/`outputs` 描述（`required`/`type`/`register`/`description`）。

**评估**：✅ Phase C 编译器可直接消费 formalSpec 构造地址映射

## 3. 关键设计决策（Phase B 内累积）

### D-B01-1：fs 错误码白名单（ENOENT/EACCES/EISDIR → 数据）
- 原则：用户能预测的常见错误数据化
- 实现：`file-read.ts`/`grep-search.ts` 统一 catch + code 判断

### D-B02-1：MVP 不实现原子写入
- 扩展点：注释说明 write-to-temp + rename 实现位置
- 决策理由：复杂度 vs 收益（MVP 测试不依赖强原子性）

### D-B03-1：execFile 而非 exec（防 shell 注入）
- 安全约束：`execFile` + 参数数组化
- 测试覆盖：`; rm -rf /` 字面量验证不执行

### D-B03-2：MVP 实现 timeout（默认 30s）
- 实现：SIGTERM → TIMEOUT 错误码
- 决策理由：30s 是合理上限；不实现会使用方无限等待

### D-B04-1：fs.promises.glob（Node 22+ 内置）
- 类型绕过：`fs as FsWithGlob` cast（@types/node 20 不识别）
- 实现：`cwd` 显式 stat 检查（fs.glob 在 cwd 不存在时不一定抛错）

### D-B06-1：and/or 改为二元输入
- 原设计：`list<boolean>` 多元（不可行，Address 无法嵌套）
- 修正：二元（a + b），多条件通过嵌套 and 实现
- 影响：formalSpec 更新 + 集成测试修正

### 4.1 验证 D-A10-1 设计

**B01-B06 验证**：
- ✅ 所有 op 抛出的异常都是"未知/不可预测"（如 fs EMFILE、spawn EAGAIN、TypeError 等）
- ✅ 已知错误码已数据化（用户可在 L3 编译时通过 `extract_error_code` + `equals` 判断）
- ✅ 测试覆盖：tier-b01 / tier-b06 集成测试均验证 throw 走 L1 冒泡

### 4.2 extract_error_code（D-B06-2）

**作用**：L3 编译 conditional_judgment.trigger 时，从 $r_err 取 code 判断（如 ENOENT vs EACCES 不同处理）

**测试**：tier-b06 集成测试"错误码提取 + equals(ENOENT)"已覆盖 ✓

### 4.3 Phase C 准备就绪

L3 编译器可立即使用以下 op 构造 conditional_judgment DAG：

```typescript
move('op_err', $r_err)               // 准备错误对象
execute_op('extract_error_code',     // 取 code
  { error_obj: $r_err }, 
  { code: $r_code })
execute_op('equals',                  // 比较 code
  { a: $r_code, b: $r_expected_code },
  { result: $r_cond })
conditional_skip($r_cond, elseBlock) // 决策
```

### 7.2 风险与决策点

**风险 1**：经验库 < 50 条是否足够？
- doc 04 §3.2 MVP 标准意图库：< 50 条
- 风险：MVP 用户场景可能需要更多
- 决策：先做 8-10 条核心经验（如 file_edit / run_shell / search_replace），边用边加

**风险 2**：conditional_judgment 编译时 DAG 复杂度
- 多条件嵌套 → DAG 长度可能爆炸
- 决策：保持 and/or 二元，多条件 = 嵌套；DAG 长度可控

**风险 3**：E2E 测试需要真实 LLM mock
- Phase C 模拟 LLM 输出 → Experience → 执行
- 决策：mock-l3 已有 programmatic 接口，扩展为"经验序列生成器"
