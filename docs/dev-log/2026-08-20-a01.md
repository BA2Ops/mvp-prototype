### 2. 设计要点

#### 2.1 状态机字段

- **OpEntry.status**：3 种状态（pending → running → done）
- **IntentEntry.phase**：4 种状态
  - `pending`：刚进入，等待调 L3.compile
  - `awaiting_children`：children 已压栈，等待完成
  - `done`：所有 children 完成
  - `aborted`：被硬错误中止

#### 2.2 命名约定

- **variable name**：以 `$` 开头（与 `$env.*` 环境上下文区分）
- **Address.kind**：3 种（literal/variable/file）

#### 2.3 类型缩窄

- StackEntry 是 discriminated union（通过 kind 字段缩窄）
- 提供 5 个 type guard 函数（isOpEntry 等）
- 提供 assertNever 用于 switch default 分支

## 设计决策

### D1. StandardIntent.children 用 unknown[]

**理由**：A1 阶段只定义最小版本。具体 child 结构（op/sub_intent/if）在 Phase C 完整定义。

### D2. IntentEntry.intent 是 union 类型

```typescript
intent: RecognizedIntent | StandardIntent
```

**理由**：
- LLM 直接识别出的意图（RecognizedIntent）需要立即执行
- 标准意图库中的意图（StandardIntent）有完整 children 描述
- 两者都需要支持 execute_intent

### D3. 提供 type guard 函数

**理由**：类型缩窄可以用 `entry.kind === '...'` 或 `isOpEntry(entry)`。两种方式都支持，提供 guard 函数增加可读性。

### D4. assertNever 在 default 分支使用

```typescript
switch (entry.kind) {
  case 'execute_op': ...
  case 'execute_intent': ...
  // ...
  default:
    return assertNever(entry)  // 编译期检查所有 case 都被处理
}
```

**理由**：新增 primitive 时如果忘记处理某个 kind，编译会报错。
