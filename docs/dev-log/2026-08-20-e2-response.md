# E2: 信息返回权在 L3（D-E2-1）— 人类用户预期差距修复

**日期**：2026-08-20
**触发**：用户评审 demo 体系时提出关键问题——「demo 预期的能力结果是否符合正常人类用户预期？」

---

## 1. 实证发现的差距

用「普通用户会说的话」实测，发现 5 项差距：

| # | 差距 | 实证 |
|---|---|---|
| 1 | **失败静默**（最严重） | `读取 ghost.txt` → 主输出 `null`，错误埋在 $r_err 用户看不到 |
| 2 | 结果是机器视角 | bytes=1 / count=0 / [] 对人类无意义 |
| 3 | 破坏性操作无提示 | write_file 静默覆盖已有内容 |
| 4 | 无法识别抛英文技术异常 | 而非引导性回复 |
| 5 | 表达刚性 | mock LLM 固有限制（真 LLM 可解，不在本次范围）|

**根因**：不是引擎 bug——L1/L2/L3 行为全部正确。缺的是「结果 → 人话」的最后一层。

## 2. 设计决策 D-E2-1：信息返回权在 L3

**用户裁定**：修复应通过增强 L3 经验的处理逻辑——经验自己定义正确/错误时的
消息模板；L4 拿到确定的信息后只做渲染。

这与「错误处置权在 L3」（D-A10 系列）同构：
- 失败时做什么 → L3 决定（handleError）
- 成功/失败说什么 → L3 决定（response/failure 模板）
- L4 只翻译，不判断业务含义（"文件不存在" vs "权限不足"只有 L3 懂）

### 实现

1. **`TargetOpPath.response?: string`** — 每条路径的结果消息模板。
   分支语义 → 分支消息（safe_write 的 do_write="已写入…" / abort="已存在，跳过"）。

2. **`Experience.responses.failure?: Record<string,string>`** — 按 `$r_err.code`
   映射失败消息（'*' 兜底）。执行后 $r_err 非空时优先于成功消息——失败显性化。

3. **编译器路径标记**：分支构造在 THEN/ELSE 块首各插入一条
   `move(literal pathId, $r_path)`，运行时可查实际走过的路径。
   标记计入块长度，cskip/skip_n 计算自动正确。

4. **`src/l3/response.ts` resolveResponse()**：
   优先级 = failure[err.code] > path.response（按 $r_path）> default_path.response
   > "已完成 <id>"。插值变量：{param} 输入参数 / {register} 寄存器去前缀 /
   {err.code} {err.message}。未知变量保留原样（不静默吞掉）。

5. **pipeline**：SayResult 增加 `message`；识别失败不再抛异常，
   返回 ok=false + 引导性回复（能力清单来自 L3 listExperiences 的业务描述）。

## 3. 效果对比

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 读缺文件 | 主输出 null，无解释 | 「读取失败：文件 X 不存在」|
| 缺文件读默认 | 只返回内容 | 「文件 X 不存在，已使用默认内容」|
| safe_write 跳过 | bytes=0 | 「文件 X 已存在，按安全模式跳过写入」|
| 替换完成 | count=1 | 「替换完成：X 中共替换 1 处并已保存」|
| 讲个笑话 | 英文异常 + stack trace | 「我没有理解…目前我能处理这些操作：…清单」|
