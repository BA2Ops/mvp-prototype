## 2. 被推翻的设计假设（重写记录）

### 2.1 「12 个独立条件 op」→ 单 evaluate_expr ⭐ 最大修正
- **原假设**：条件判断拆成 equals/gt/and/is_truthy/... 独立 op
- **推翻原因**：D-FB-1 反思——L1 直接使用的条件 op 为**零个**；表达式求值是单一关注点，12 个 op 是错误的关注点切分，且加重 L3 组合负担
- **修正后**：evaluate_expr（JSON AST 求值器）单 op；JudgmentTrigger 直接存 Expr 树；条件 DAG 长度 5-6 → 1
- **教训**：**每个 op 必须有真实使用方**——这条原则应前置到设计期

### 2.2 ParamRef.kind='preprocessing' → 删除
前置输出本质是 named register，专用引用类型是冗余抽象。

### 2.3 l1MainLoop 根帧 handleError 恒 false → 补 rootHandleError 选项
C6 E2E 暴露：错误处置权在 L3 的设计没有贯通到根帧。接口缺口由测试驱动补全。

### 2.4 计划的 Phase D 五 tier → 实际一个场景 tier
层间集成被 Phase C 的 E2E 自然覆盖——迭代式原型的好处：后续阶段范围随实际进度收缩。

## 5. 已知取舍与遗留（按优先级）

1. **链式经验中间错误不拦截**：replace_in_file 步骤失败带 null 继续走。
   改进：编译器为 handleError 经验自动插入步骤间错误检查跳转。
2. **嵌套 params 不支持 register 引用**（D-C6-1）：全局寄存器方案已绕过大半场景，
   剩余需要「按值传参」的场景待补。
3. **多 judgment 链 else_path 组合语义**：当前 else_path 优先、无则递归链式，复杂组合未测。
4. **recompile 无重试策略**：MVP 与 compile 相同，策略留给上层。
5. **feedback_history 仅存储**：经验演化是 Phase 后话题。
6. **evaluate_expr 无 lambda**：map/filter 内联函数不支持（< 50 条经验不需要）。

## 结语

MVP 用 **557 个测试**验证了完整设计闭环：
自然语言进来，经过 L4 识别 → L3 经验编译 → L1 取指执行 → L2 真实操作，

CPU 类比（取指循环/CALL 帧/Jcc/异常展开）自始至终精确。
