# A11 开发日志 — 递归深度跟踪（enterIntent / exitIntent）

日期：2026-08-20
前置：A10（异常冒泡 + 帧保留 + handleError）

---

## 一、背景与目标

循环通过**递归 intent 引用 + conditional_skip** 实现（D22，不增加 loop primitive）。
这意味着失控递归（经验库作者 bug：循环终止条件写错）会无限展开——需要安全网。

**目标**（doc 11 Phase A11）：
- 实现 enterIntent / exitIntent（按 intent.type 计数调用链深度）
- 默认上限 1000，超限抛错（防御）
- **反思触发**：若深度跟踪与 execute_intent 耦合 → 解耦

## 二、设计决策

### D-A11-1: 深度跟踪独立模块（解耦）

`src/l1/recursion.ts`（enterIntent / exitIntent / RecursionDepthError / DEFAULT_MAX_RECURSION_DEPTH）。

**enter/exit 调用点在主循环**（帧生命周期管理者），`execute-intent.ts` 保持纯"编译 + 压栈"：

| 时机 | 调用 | 位置 |
|---|---|---|
| 帧激活（pending → compile）| enterIntent | processIntentEntry pending 分支 |
| 帧正常完成（children 全部执行完）| exitIntent | processIntentEntry awaiting_children 分支 |
| 帧被冒泡弹出（aborted）| exitIntent | bubbleError（abortFrame 辅助）|

**enter/exit 成对保证**：帧只有两条回收路径（done / aborted），都 exitIntent。
冒泡弹出时判断 `phase !== 'pending'` 才 exit（pending 帧未 enter——enter 在 phase 改变前）。

### D-A11-2: 计数颗粒度 = intent.type

`recursionDepth: Map<string, number>`——同一 intent 的递归累加，不同 intent 独立计数。
（与 D29 一致；间接循环 A→B→A 不计数但 maxSteps 兜底。）

### D-A11-3: RecursionDepthError 不走业务冒泡

与 L1MaxStepsError 同类（D-A10-6 语义）：若被 handleError 截获，递归经验可无限重试——
防御机制失效。l1MainLoop catch 中 `err instanceof RecursionDepthError → 直接 throw`。

**实现细节**：enterIntent 在 processIntentEntry 内（try 内），超限抛错时帧 phase 仍为
'pending'（enter 先于 executeIntent），冒泡不会误判为已 enter 的帧。

### D-A11-4: 帧边界保护细化（skip 可跳过 pending 帧）

**发现问题**：A10 帧边界保护"skip 遇到 IntentEntry 帧停止弹出"与循环终止**冲突**——
循环模式 `cond_skip(stop, n=1) → execute_intent(self)` 需要 skip **跳过 self 帧**（不执行子调用），
否则无限递归。

**细化**（skip-n.ts + conditional-skip.ts）：

```
- pending 帧（未开始的子调用）：允许跳过 = 不执行它（循环终止）
- awaiting_children / aborted 帧（执行中/已结束）：停止弹出（保护调用边界）
```

**安全性**：pending 帧无 children（未编译），跳过它不会误跳帧内部内容；
执行中的帧（awaiting_children）仍在调用链上，skip 跨它会破坏异常展开。A5/A6
帧边界测试用 awaiting_children 帧，不受影响。

## 三、发现并修正 doc 10 §6.5 的文档错误

循环 Walkthrough 轨迹中 conditional_skip 的 truthy 语义**写反了**（与 doc 06 §3.5 矛盾）：

```
❌ 原（错误）：cond_skip true → 仅 pop self（继续）；false → pop self + 1（终止）
✅ 修正：       cond_skip 检查**终止信号**：truthy → 跳过 self（终止）；falsy → 继续
```

- 编译结果：`check_max` 输出改名 `$should_stop`（truthy = 达到上限）
- Iteration 1-4: stop=false → 继续递归；Iteration 5: stop=true → 跳过 A_self_5 → 终止
- D30/D32 示例同步修正（`while $should_stop == false`）
- 新增"关键观察"：skip 可跳过 pending 帧（A11 帧边界细化）

## 四、测试（tier-a11-recursion.test.ts，17 个）

**单元（recursion.ts）**：
- enterIntent 递增 / exitIntent 递减 / 归零删键 / 未 enter 防御 / 独立计数
- 超限抛 RecursionDepthError（含意图名+深度）/ Error 子类 / 默认 1000 / 边界（next === max 允许）

**集成（l1MainLoop）**：
- 有限递归（countdown 0→3，stop 条件）→ 正常完成 + 深度归零 + 栈空
- maxRecursionDepth 边界：3 允许 / 2 超限
- 无限递归 → RecursionDepthError 给调用者
- **不走冒泡**：handleError=true 帧也不截获
- 冒泡无 handler → 全部 exitIntent（深度归零）
- 冒泡截获在 handleError 帧 → 深度保留 → 帧完成后释放
- 多层递归中异常 → 每层 exitIntent（不泄漏）
