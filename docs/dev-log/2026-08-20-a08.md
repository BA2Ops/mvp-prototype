## 三、实现要点

### 3.1 核心流程（5 步）

```typescript
export async function executeIntent(entry, state): Promise<void> {
  // Step 1: 标记 awaiting_children
  entry.phase = 'awaiting_children'
  // Step 2: 调 L3 compile（可能抛错，向上传播）
  const children = await state.l3.compile(entry.intent, state)
  // Step 3: pop 自身（关键顺序！）
  state.stack.pop()
  // Step 4: 逆序 push children
  for (let i = children.length - 1; i >= 0; i--) {
    state.stack.push(children[i])
  }
  // Step 5: 标记 done
  entry.phase = 'done'
}
```

### 3.2 关键决策

**D-A8-1: pop 自身必须先于 push children**

最初实现是"push children 再 pop"，导致 pop 弹出的是刚压入的 children 而非 IntentEntry。
JS Array.pop() 移除**栈顶**（数组末尾），children push 到栈顶后 pop 必然弹 children。

正确顺序：**先 pop（entry 在栈顶，L1 主循环保证）→ 再逆序 push children**。

**D-A8-2: 栈数组方向约定**

- 数组末尾 = 栈顶 = 下一个执行（`stack.pop()` 取）
- children = [A, B, C]（L3 返回，A 先执行）→ 栈数组（底→顶）= [C, B, A]
- 首次测试断言写反（期望 [A, B, C] 数组顺序），修正为 pop 顺序验证

**D-A8-3: L3 compile 抛错 → 向上传播**

不 catch。entry 停在 `awaiting_children`，由 A10 propagateHardError 决定 abort/重试。

**D-A8-4: IntentEntry.intent 类型统一为 RecognizedIntent**

原类型 `RecognizedIntent | StandardIntent`。Experience 模型取代 StandardIntent 后，
移除 StandardIntent 定义，IntentEntry.intent 仅 RecognizedIntent（type 由 L4 标准化）。

### 3.3 错误处理

| 错误 | 处理 |
|---|---|
| L3 compile 抛错 | 向上传播（不 catch）|
| children 为空 | 正常完成（done + pop）|
| IntentEntry 类型异常 | 理论上类型保证不会发生（ExecuteIntentError 保留备用）|

## 六、发现的问题与修复

**问题 1：pop 顺序错误**（实现 bug）
- 症状：children 压栈后 pop 弹出 children 而非 IntentEntry
- 修复：调整 Step 3/4 顺序（先 pop 自身，再 push children）
- 教训：Array.pop() 移除栈顶，压栈后 pop 必然弹新元素

**问题 2：测试断言方向写反**（测试 bug）
- 症状：期望栈数组 [first, middle, last]，实际 [last, middle, first]
- 分析：实现正确（pop 顺序 first → last），是测试对"数组顺序"理解有误
- 修复：测试改为验证 pop 顺序（更有语义），而非数组顺序
