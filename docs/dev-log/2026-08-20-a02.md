## 发现的问题

### 问题 1：测试结构错误（已修复）

**现象**：第一次写测试时，`beforeEachInit()` 是普通函数调用，不是 vitest hook。

**根因**：我把 helper 函数命名为 `beforeEachInit()`，看起来像 hook，实际只是普通函数。它只在 describe 块 setup 时执行一次，不是每个 test 前执行。

**影响**：state 在测试间共享，导致测试相互污染（某些测试通过可能是因为之前测试的副作用）。

**解决**：用 vitest 的 `beforeEach` hook：

```typescript
describe('resultStore 基础操作', () => {
  let state: ExecutionState

  beforeEach(() => {
    const { registry: l2 } = createMockL2()
    const l3 = createMockL3([])
    state = createInitialState(l2, l3)
  })

  test('set/get 读写值', () => {
    state.resultStore.set('$x', 42)
    // ...
  })
})
```

**学习**：测试 helper 函数命名要清晰，避免与 vitest hook 名混淆。

### 问题 2（设计层面）：L3Service 应该在生产代码还是 mock？

**决策**：在生产代码中定义。

**理由**：
- 反向依赖正确：production → types, mock → implements types
- 未来替换 mock 为真实 L3 实现时，无需修改 ExecutionState
- A0 阶段先把 L3Service 放在 mock 是临时方案，A2 应该修正

## 设计决策

### D1. resultStore 直接用 Map，不用 wrapper

**理由**：
- Map 已有 set/get/has/delete，足够用
- 增加 wrapper 增加复杂度，无明显收益
- A3+ 如需特殊语义再增加 wrapper

### D2. key 不必以 $ 开头（A2 阶段）

**理由**：
- A2 是简化版本，不做格式校验
- A3+ Address 解析会引入完整规则
- 测试覆盖了 "key 不必以 $ 开头"，明确这是临时状态

### D3. ExecutionState 是单一对象

**理由**：
- 避免传递多个参数（l2, l3, stack, resultStore）
- 所有 primitive 执行函数共享同一 state
- 单一引用对象，便于 mock 和测试

### D4. 不立即添加 recursionDepth / logger / 等扩展字段

**理由**：
- A2 阶段严格按计划只做最小版本
- A11 添加 recursionDepth
- logger 在后续 Phase E 集成
- 避免过早设计
