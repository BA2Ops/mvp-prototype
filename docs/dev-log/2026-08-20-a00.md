**注意**：这些类型在 A0 是最小子集，完整版本在 A1/A2/Phase B 定义。

### 3. Mock 基础设施

**MockOpTracker**（`src/mocks/mock-l2.ts`）：
- 记录所有调用（op name + inputs）
- 提供 getCalls() / getCallCount() / reset()

**createMockL2()**：
- 内置 `mock_op`：x → x*2

## 发现的问题

### 问题 1：mock-l2.ts 用了 `require()`

**现象**：第一次写 mock-l2.ts 时用了 `require('../l2/registry.js')` 来延迟导入（避免循环依赖）。

**根因**：我以为 require 在 ESM 中可用，实际上不行。

**解决**：直接用静态 `import { L2Registry } from '../l2/registry.js'`，因为没有循环依赖。

**学习**：ESM 项目必须用静态 import，require() 不可用。

### 问题 2：tsconfig.json 的 rootDir 与 tests 冲突

**现象**：`npm run typecheck` 报"tests/helpers.ts is not under rootDir"。

**根因**：tsconfig.json 的 rootDir = ./src，但 include 也包含 tests/**/*。

**解决方案**：
- 创建独立的 `tsconfig.test.json` 用于类型检查（包含 tests，无 emit）
- `tsconfig.json` 只包含 src（用于 build）

**学习**：Vitest 自己处理 TypeScript 编译，不需要 tsc emit 测试代码。

### 问题 3：build 命令创建了 .js 文件污染 src/

**现象**：第一次 build 后，src/ 和 tests/ 旁边出现了 .js 文件。

**根因**：tsconfig 没有 outDir，tsc 默认输出到源文件旁边。

**解决**：在 tsconfig.json 添加 `"outDir": "./dist"` 和 `"rootDir": "./src"`。

## 反思与收获

### 收获 1：Mock-first 原则的实际好处

写测试时，mock L2 的简单接口（x → x*2）就能验证 tracker、调用记录等所有关键功能。
**不需要真实 IO**，测试运行 680ms（包含 vitest 启动）。

### 收获 2：预先定义类型是必要的

为了让 mock 编译，必须先有 Operation 接口、Value 类型等。
这意味着 A0 的范围比预期大一点**——必须包含这些最小类型**。

### 收获 3：独立 tsconfig.test.json 是个好做法

让生产构建（src only）和测试检查（src + tests）分离，互不干扰。

### 收获 4：TypeScript strict 模式是好的早期投资

strictNullChecks 在写 mock 时立刻发现了几个潜在 bug（如 throw 后的返回值处理）。
