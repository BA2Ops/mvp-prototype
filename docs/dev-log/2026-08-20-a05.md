## 目标

实现 skip_n primitive —— L1 5 个 primitive 中最简单的：
- 弹出 self + n 个后续 entry
- 不访问 Address（与双区无关）
- 不调用 L2/L3
- 仅操作指令栈

## 设计决策

### D-A5-1: n 的语义

`n` 是**包含 self 的总弹出数减 1**：
- `n=0`：弹 1 个（仅 self）
- `n=1`：弹 2 个（self + 1 个后续）
- `n=3`：弹 4 个（self + 3 个后续）

这个语义在 doc 06 §3.4 中明确："跳过的 entry 数（包含 self）"。

### D-A5-2: 边界处理（graceful）

当栈不足时（请求弹出数 > 栈大小）：
- **不抛错**
- 弹空为止
- 这是更宽松的语义，便于容错

理由：skip_n 是控制流指令，应该尽可能灵活。如果上层（DAG 编译器）出错导致 n 过大，应该是编译器责任，不是 runtime 责任。

### D-A5-3: n < 0 抛错

MVP 约束："仅支持前向跳转（n ≥ 0）"。

实现：抛 `SkipNError`，明确告知调用方 MVP 范围。

### D-A5-4: 不修改 state

skip_n 只动栈，不动：
- `publicStore` / `internalStore`
- `allocator`
- `l2` / `l3` 引用

验证通过测试。

## 实现

### 文件

`src/l1/primitives/skip-n.ts` (~45 行)：
- `executeSkipN(entry, state)` 函数
- `SkipNError` 类

### 关键代码

```typescript
export async function executeSkipN(
  entry: SkipN,
  state: ExecutionState
): Promise<void> {
  if (entry.n < 0) {
    throw new SkipNError(
      `skip_n.n must be >= 0 (MVP: only forward jumps), got ${entry.n}`
    )
  }

  const totalPops = entry.n + 1
  for (let i = 0; i < totalPops; i++) {
    if (state.stack.length === 0) break
    state.stack.pop()
  }
}
```

## 反思与发现

### R1: 栈布局理解的坑

第一次写测试时，`push` 顺序理解反了。例如：

```typescript
// 错误：
state.stack.push(skip)             // skip 在底部
state.stack.push(createMarker('m')) // marker 在顶部
// pop() 弹 marker（顶部），不是 skip（底部）
```

修正后：

```typescript
// 正确：
state.stack.push(createMarker('m')) // m 在底部
state.stack.push(skip)                // skip 在顶部（要被执行）
// pop() 弹 skip（顶部）
```

**教训**：写栈测试时，明确画出"底→顶"图。

### R2: skip_n 在 DAG 中的真实位置

skip_n 总是出现在栈的"中间偏下"位置（不是顶层），因为：
1. L1 main loop 弹出栈顶
2. 栈顶是当前要执行的 entry
3. skip_n 在条件分支编译产物中位于 else_block 之后、then_block 之前

实际执行序列：
```
栈底→顶: [parent_intent, then_block, skip_n, else_block, cond_skip, op_entry]
                                                              ^^^^^^^ 顶层（被 L1 弹）
执行顺序：
1. op_entry 执行 → pop
2. cond_skip（条件为真）→ 弹 cond_skip + else_block + skip_n（n=2 跳过它们）
3. then_block → pop
4. parent_intent 完成 → pop
```

我们测试的 `n=0` 场景是简化版（假设前面都执行完了，只剩 skip_n）。

## 备注

A5 是最简单的 primitive，是后续 A6/A7/A8 的基础。它的简单性体现在：
- 无 Address 操作
- 无 L2/L3 调用
- 无错误传播（除 n<0 校验）
- 仅栈 LIFO 操作

这种"基础设施"性质的 primitive 应该最先完成，为后续复杂 primitive 提供信心。
