## 目标

实现 conditional_skip primitive —— L1 5 个 primitive 中**与计算分离的判断指令**：
- 读 internalStore 中的条件值（双区架构约束）
- truthy 判断
- 条件为真 → 弹 self + n 个后续 entry
- 条件为假 → 仅弹 self

## 设计决策

### D-A6-1: conditionAddr 必须是 internal（双区架构约束）

**决策**：运行时校验 `isInternalAddress(entry.conditionAddr)`。

**理由**：
- L1 调度器只识别寄存器地址
- 业务命名（public）、字面量（literal）、文件（file）不应被 conditional_skip 直接读
- 与 execute_op 约束一致

**违规处理**：抛 `ConditionalSkipError`。

### D-A6-2: truthy 规则（与 doc 06 §3.5 一致）

```
null/undefined → false
boolean → 本身
number → !== 0
string → 非空
array → 非空
object → 非空
其他 → Boolean(value)（防御性）
```

特别为错误处理优化：
- `$r_err = null`（成功）→ falsy → 跳过错误分支 → 执行成功路径
- `$r_err = OperationError`（失败）→ truthy → 执行错误分支

### D-A6-3: 内部寄存器不存在视为 falsy（graceful）

**决策**：`state.internalStore.get(regName)` 返回 `undefined` 时视为 falsy，不抛错。

**理由**：
- 等价于"条件值未初始化"，DAG 顺序执行下理论上不应发生
- 但若发生，falsy 行为是"跳过 self + 继续"，符合"条件不满足"语义
- 抛错会让 DAG 在边缘情况下完全崩溃，影响健壮性

**反例**：如果 strict 模式要求"未初始化 = 错误"，DAG 调试反而困难。

### D-A6-4: 与 CPU 跳转指令的类比

| 真实 CPU | 本设计 |
|---|---|
| x86 Jcc（条件跳转） | `conditional_skip` |
| CMP/SUB 设置 FLAGS | `execute_op`（比较/逻辑 op） |
| FLAGS 寄存器（隐式） | `internalStore` + conditionAddr |
| 标志位（ZF/CF/SF） | truthy 判断规则 |

**关键洞察**：**计算与跳转分离**——`execute_op` 写入结果，`conditional_skip` 只读判断。这与 x86 的 Jcc 模式一致，但**不是** RISC-V 的 BEQ（直接比较两寄存器）模式。

### D-A6-5: 条件计算 op 族（推迟到 Phase C）

参见 [doc 06 §7.2.1](../docs/mvp/06-execution-layer.md#721-条件计算-op-族2026-08-20-新增)：

- **MVP 必需**：equals, not_equals, gt, lt, and, or, not, is_empty, is_truthy, extract_error_code
- **MVP 强烈建议**：gte, lte
- **MVP 推迟**：in, between（可由已有 op 组合）

### 关键代码

```typescript
export async function executeConditionalSkip(
  entry: ConditionalSkip,
  state: ExecutionState
): Promise<void> {
  // 1. 校验 conditionAddr.kind
  if (!isInternalAddress(entry.conditionAddr)) {
    throw new ConditionalSkipError(
      `conditional_skip.conditionAddr must be internal (got '${entry.conditionAddr.kind}'). ...`
    )
  }

  // 2. 校验 n >= 0
  if (entry.n < 0) {
    throw new ConditionalSkipError(
      `conditional_skip.n must be >= 0 (MVP: only forward jumps), got ${entry.n}`
    )
  }

  // 3. 读取条件值（不存在的寄存器视为 falsy）
  const condValue = state.internalStore.get(entry.conditionAddr.name)

  // 4. truthy 判断
  const truthy = isTruthy(condValue)

  // 5. 弹栈
  if (truthy) {
    for (let i = 0; i <= entry.n; i++) {
      if (state.stack.length === 0) break
      state.stack.pop()
    }
  } else {
    state.stack.pop()
  }
}
```

## 反思与发现

### R1: vitest v8 provider 给 `}` 闭合行打分支标记

第一次写 `Object.keys(value).length > 0` 时，v8 报告 `>0` 是 cbranch-no。

**根因**：V8 引擎做常量折叠优化，把 `Object.keys({}).length === 0` 内联为 `0 > 0` = false。v8 跟踪器认为"常量表达式只有一个可能值"，但 vitest v8 provider 仍把 `>` 当作分支。

**修复**：
- 重写为显式 if 块：`if (typeof === 'object') { const isEmpty = ...; return !isEmpty }`
- 但 vitest v8 给 `}` 闭合行也打 cbranch-no（quirk）

**最终结果**：statements 100%, functions 100%, lines 100%, branches 95.83%（vitest quirk）

### R2: 防御性 fallback 用 v8 ignore

`return Boolean(value)` 是为 symbol/bigint/function 等极少 JS 类型准备的兜底。用 `/* v8 ignore next 3 */` 标记并附说明。

### R3: 与 x86 跳转指令的精确类比

确认 conditional_skip 是"判断"而非"计算"，对应 x86 Jcc 而非 BEQ/CMP。这进一步巩固了"计算 op 是 L2 层、conditional_skip 是 L1 层"的边界。

### R4: 文档同步

A6 暴露了一个文档缺口：L2 内置 8 op 清单里没有"比较/逻辑 op"，但 DAG 条件分支示例里隐含使用。已在 doc 06 §7.2.1 补充条件计算 op 族清单 + MVP 范围决策（最小集 + 2 实用、推迟复合 op）。
