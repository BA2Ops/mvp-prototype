## 2. 关键设计决策（Phase C 累积）

### D-C1-1：删除 `ParamRef.kind='preprocessing'`
前置输出的本质是「写入了某个 named register」，用 `register` 引用即可。简化编译逻辑，经验定义可自由引用任意中间结果。

### D-C2-1：JudgmentTrigger 用 Expr JSON AST
（承接 evaluate_expr 重构）`condition_expr` 替代 `condition_op + compare_value`。编译器构造单个 `evaluate_expr` op + `conditional_skip`，DAG 长度 5-6 → 1。

### D-C4-1：输入绑定约定
`intent.params[k]` / schema default → `move(literal, $r_input_<k>)`。schema 外的多余参数宽容绑定（便于调试透传）。

### D-C4-2：skip_threshold 过滤语义
`skip_cost >= threshold && threshold > 0` → 整体跳过（不生成 entry）。threshold=0 必跑；skip_cost 经 `ExperienceService` 构造参数注入（`executeIntent` 调 compile 不传 options 的 MVP 约定）。

### D-C4-3：运行时分支的规范构造 ⭐
"if c then T else E" 用 L1 primitives 实现（源头取反）：

```
[0] move(literal not(c) AST, $r_cond_<j>)
[1] execute_op(evaluate_expr, expr=$r_cond, result=$r_judge, error=$r_err)
[2] conditional_skip($r_judge, n = len(T)+1)
[3..] T（then 块）
[.]  skip_n(len(E))        ← T 尾部
[..] E（else 块）
```

轨迹验证（写入 compiler.ts 文档头）：
- c=true → ¬c=false → cskip 仅弹自己 → T 执行 → 尾部 skip_n 弹掉 E ✓
- c=false → ¬c=true → cskip 弹 self+len(T)+1（T+尾部 skip）→ E 执行 ✓

多 judgment 链：else 无显式 path 时递归后续 judgments（if-else-if 链）。

### D-C4-5：handleError 处置权贯通 ⭐
- `Experience.handleError?: boolean`（LLM 按业务语义设置）
- 嵌套调用：编译器写入 `IntentEntry.handleError`
- **根帧**：`l1MainLoop` 新增 `options.rootHandleError`（C6 暴露的 L1 缺口——此前根帧恒 false，调用方无法传入处置权）

### D-C6-1：嵌套调用 params 限制（MVP）
仅支持 literal / input 引用。register 引用需运行时求值，而 `intent.params` 是静态值——编译期抛错（有测试验证）。后续版本可扩展。

## 3. 错误处理全场景验证（A10 设计 → C6 实战）

| 场景 | 机制 | C6 验证 |
|---|---|---|
| L2 已知错误（ENOENT 等） | 数据化写 `$r_err`，DAG 用 evaluate_expr+cskip 分支 | C5: read_file_with_default / safe_write |
| L2 未知异常（ERR_INVALID_ARG_VALUE） | throw → bubbleError → 找最近 handleError 帧 | C6-S2/S3 |
| 子帧自处理 | 子 handleError=true → 子帧保留，执行完 pop，父继续 | C6-S2: 父读到 `$r_err` ✓ |
| 父帧截获 | 无标志子树丢弃，**父剩余 children（catch 逻辑）保留** | C6-S3: catch 步骤执行 ✓ |
| 无处理器 | 全弹栈 → `UnhandledError` 抛给调用者 | C6-S4 ✓ |

**「错误处置权在 L3」从设计到实现全链路一致。**
