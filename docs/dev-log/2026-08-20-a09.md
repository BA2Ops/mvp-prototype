## 一、任务

实现 L1 调度器主循环 `l1MainLoop` —— 把 5 个 primitive 集成到统一执行循环。

## 二、设计

### 2.1 核心结构

```typescript
export async function l1MainLoop(
  rootIntent: RecognizedIntent,
  state: ExecutionState,
  options?: L1RunOptions
): Promise<void> {
  // Step 1: 压入根意图
  state.stack.push(createRootIntentEntry(rootIntent))

  // Step 2: 主循环（5-case 严格穷尽）
  while (state.stack.length > 0) {
    const top = state.stack[state.stack.length - 1]
    switch (top.kind) {
      case 'move':             await executeMove(top, state); break
      case 'execute_op':       await executeOp(top, state); break
      case 'execute_intent':   await executeIntent(top, state); break
      case 'skip_n':           await executeSkipN(top, state); break
      case 'conditional_skip': await executeConditionalSkip(top, state); break
      default: assertNever(top)  // 编译期穷尽检查
    }
  }
}
```

### 2.2 关键决策

**D-A9-1: 终止保证**
MVP 无反向跳转（skip_n 仅前向），每次迭代要么 pop（5 种 primitive 都会 pop 或 push 有限 children），要么 push 有限个 children。理论上必然终止。maxSteps 是防御性保护（递归经验深展开）。

**D-A9-2: 错误处理（A9 骨架版）**
硬错误直接向上传播（不 catch）。栈清理留给 A10 propagateHardError。测试验证了"错误后栈保留"作为 A10 的前置状态。

**D-A9-3: execute_intent = CALL 语义**
基于 A8 的 executeIntent（一次性：pop self → push children）。与 doc 10 §3 旧 DAG 模型（processIntentEntry 两阶段 + aggregate）不同——Experience 模型的 children 是线性序列，不需要聚合。

**D-A9-4: assertNever 穷尽检查**
default 分支用 assertNever（编译期检查新增 kind 必须处理）。这是防御代码（运行时不可达），v8 ignore 标记。

## 四、发现的问题

**问题：5-case 完整性测试失败**
- 症状：`$r1` undefined（op 未执行）
- 原因：测试用 createProgrammableL3 但只注册了 'inner'，根意图 'all_kinds' 未注册 → compile 返回空
- 修复：补 `l3.setChildren('all_kinds', children)`
- 教训：programmable L3 按 type 路由，根意图 type 必须注册
